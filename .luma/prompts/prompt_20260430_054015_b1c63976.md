## Summary

This PR implements a comprehensive VCS CLI abstraction layer that enables Luma to work with both GitHub CLI (`gh`) and GitLab CLI (`glab`). The implementation maintains full backward compatibility while providing users with the flexibility to choose their preferred VCS tool through configuration.

## Features

### ✅ VCS CLI Abstraction
- **Configurable Selection**: Choose between `gh` and `glab` via `VCS_CLI` environment variable
- **Backward Compatibility**: Default behavior unchanged (uses `gh`)
- **Token Management**: Smart fallback chain: `VCS_TOKEN` → `GITLAB_TOKEN` → `GITHUB_TOKEN`

### ✅ GitLab Integration
- **Issue Fetching**: Full support for GitLab issue listing and parsing
- **Command Conversion**: Automatic translation of GitHub commands to GitLab equivalents

### ✅ Enhanced Logging & Debugging
- **File-based Logging**: Detailed CLI operation logs in `.luma_logs/`
- **Command Tracking**: Full visibility of which CLI tool and commands are executed
- **Error Classification**: Clear error messages for CLI-specific issues

## Configuration

### Environment Variables
```bash
# Use GitHub CLI (default)
VCS_CLI=gh
GITHUB_TOKEN=your_github_token

# Or use GitLab CLI
VCS_CLI=glab
GITLAB_TOKEN=your_gitlab_token
```

### Token Fallback Chain
1. `VCS_TOKEN` (explicit override)
2. `GITLAB_TOKEN` (for GitLab CLI)
3. `GITHUB_TOKEN` (for GitHub CLI)
