## Summary

This pull request resolves the GitLab URL generation issue in PR prompts for non-Luma repositories. It ensures that dynamic URL fallback correctly handles GitLab projects while preserving exact URLs when provided by the API.

## Changes

- **URL Generation Fix**: Addressed the URL string formatting bug that caused incorrect GitLab URLs to be generated in headless PR workflows for non-Luma repositories (resolving Issue #100).
- **Core Config**: Added `"slug": "luma"` to `DEFAULT_PROJECTS` in `luma_core/config.py` to support stable project selection.
- **Documentation Updates (Headless & Workflow Phases)**:
  - Refactored the historical documentation for issues #40, #41, and #42 to align with the `#84` stable selector contract instead of fragile numeric IDs.
  - Added a new analysis document (`docs/features/30_issue-94-95-96_feature-enable-add-remove-issue-menu-options-all-b05cc03d/analysis.md`) explaining the rationale for removing phase restrictions on adding/removing issues from the interactive menu.

## Impact

- Prevents malformed issue URLs in PR descriptions for external GitLab repositories.
- Improves tracking and alignment for upcoming headless CLI developments, especially Issue #84.
- Enhances workflow flexibility by allowing add/remove issue actions across all phases.
