# Story Points Cheat Sheet

เอกสารนี้เป็นเวอร์ชันใช้งานเร็วของการให้ Story Points เพื่อช่วยตัดสินใจใน 1-2 นาที

ต้องการตัวอย่างงาน programming เพิ่มเติม: ดู [Programming Examples Appendix](/Users/oatrice/Software-projects/Luma/docs/story_points_programming_examples.md)

## สรุปสั้นที่สุด

- `0.5` = เล็กจิ๋วมาก แต่โดยปกติ **ไม่ควรใช้** ใน scale นี้
- `1` = งานเล็กมาก ชัดมาก แทบไม่มี surprise
- `2` = งานเล็ก มีรายละเอียดเพิ่มขึ้นนิดหน่อย แต่ยังตรงไปตรงมา
- `3` = งานกลาง เริ่มมีหลายขั้นตอนหรือมีจุดให้ตัดสินใจ
- `5` = งานใหญ่พอดี ต้องวางแผน และมี uncertainty พอสมควร
- `8` = งานใหญ่ มีความเสี่ยงหรือความคลุมเครือสูง ควรแยกย่อยหรือทำ spike ก่อน

## วิธีตัดสินใจเร็ว

ถามตัวเอง 5 ข้อนี้:

1. งานนี้มีหลายขั้นตอนหรือไม่
2. มีของไม่ชัดหรือสิ่งที่ต้องลองก่อนหรือไม่
3. ต้องประสานหลายคน หลายทีม หรือหลายระบบหรือไม่
4. ถ้าพลาดแล้วผลกระทบกว้างหรือไม่
5. รู้วิธีทำอยู่แล้ว หรือยังต้องค้น/ทดลองก่อน

แนวทางตีความ:

- ตอบว่า "แทบไม่มี" เกือบทุกข้อ = `1`
- มีบ้าง 1-2 ข้อ แต่ยังคุมง่าย = `2`
- เริ่มมีหลายขั้นตอนและต้องคิด = `3`
- ต้องวางแผนจริงจัง และมี uncertainty ชัด = `5`
- เริ่มใหญ่เกินหยิบทำรวดเดียว ควรแตกงาน = `8`

## ตารางจำง่าย

| Points | ความรู้สึกของงาน | ใช้เมื่อ |
|---|---|---|
| `0.5` | จิ๋วมาก | แทบไม่ควรใช้ |
| `1` | ชัดและง่าย | งานเล็กมากที่ทำตรงไปตรงมา |
| `2` | เล็ก | มีรายละเอียดขึ้นเล็กน้อย |
| `3` | กลาง | มีหลายขั้นตอน หรือมี decision point |
| `5` | ใหญ่พอดี | มี uncertainty และต้องวางแผน |
| `8` | ใหญ่ | เสี่ยงหรือกว้างจนควรแตกย่อย |

## ตัวอย่างนอกโลก programming

### งานจัดทริป

- `1`: จองร้านอาหารให้ 2 คน
- `2`: วางแผนเดย์ทริปในเมือง 3 จุด
- `3`: เดย์ทริปต่างจังหวัด ต้องกะเวลาและเส้นทาง
- `5`: ทริป 8 คน มีรถหลายคัน งบหลายแบบ และต้องจองหลายที่
- `8`: ทริปหลายวัน หลายครอบครัว มีข้อจำกัดหลายชุด

### งานเอกสาร

- `1`: แก้คำผิดและจัดรูปแบบเอกสารสั้นๆ
- `2`: เขียน memo 1 หน้า จากข้อมูลที่มีพร้อมอยู่แล้ว
- `3`: เขียน proposal ที่ต้องสรุปทางเลือกและเหตุผล
- `5`: เขียนเอกสารที่ต้องรวบรวม feedback จากหลายฝ่าย
- `8`: ทำเอกสารใหญ่ที่ต้องค้นข้อมูล ตรวจความถูกต้อง และ review หลายรอบ

### งานจัดอีเวนต์

- `1`: ซื้อเค้กหรือของขวัญอย่างเดียว
- `2`: จัดงานเล็กๆ ที่บ้าน มีของกิน 2-3 อย่าง
- `3`: นัดแขกหลายคนและจัดเวลาให้ลงตัว
- `5`: มีธีมงาน มี vendor หลายเจ้า และมีแผนสำรอง
- `8`: งานใหญ่ มีตารางกิจกรรมและข้อจำกัดหลายด้าน

### งานบ้าน/ชีวิตประจำวัน

- `1`: จ่ายบิล 1 รายการ
- `2`: เปรียบเทียบตัวเลือก 2-3 แบบแล้วตัดสินใจ
- `3`: ย้ายห้องเล็กๆ ของคนเดียว
- `5`: ย้ายบ้านพร้อมจัดการสัญญา อินเทอร์เน็ต และของหลายหมวด
- `8`: ย้ายบ้านทั้งครอบครัว พร้อมเรื่องโรงเรียน งาน และเอกสาร

### งานทำอาหาร

- `1`: ทำเมนูง่ายๆ สูตรคุ้นมือ
- `2`: ทำอาหาร 1 มื้อ มี 2 อย่าง
- `3`: ทำมื้อสำหรับหลายคน ต้องบริหารเวลา
- `5`: เมนูที่มีหลายองค์ประกอบหรือไม่คุ้นมือ
- `8`: หลายเมนูพร้อมกัน มีข้อจำกัดเรื่องอุปกรณ์และเวลา

## ข้อผิดพลาดที่พบบ่อย

- งานใช้เวลาน้อย ไม่ได้แปลว่าต้อง points ต่ำเสมอ
- งานใช้เวลานาน ไม่ได้แปลว่าต้อง points สูงเสมอ
- Story Points วัดความซับซ้อน ความเสี่ยง และ uncertainty ไม่ใช่นาฬิกาจับเวลา
- ถ้างานใหญ่จนลังเลระหว่าง `5` กับ `8` บ่อยครั้งคำตอบคือควรแตกงานก่อน

## Rule of Thumb

- ถ้าชัดมากและไม่มี surprise: `1`
- ถ้าเล็กแต่ไม่ trivial: `2`
- ถ้ามีหลายขั้นตอน: `3`
- ถ้าต้องวางแผนและเริ่มมี unknowns: `5`
- ถ้ายังคลุมเครือหรือกว้างเกินไป: `8` แล้วแตกงาน

## สำหรับโปรเจกต์นี้

- โปรเจกต์นี้ใช้ Fibonacci-style scale เป็นหลัก
- ถ้างานเล็กกว่า `1` ให้ปัดเป็น `1`
- ถ้างานเริ่มเกิน `8` ให้พิจารณาแตก issue ก่อน estimate
