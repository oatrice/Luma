# สรุปผลการทดสอบเปรียบเทียบ `gemini cli` และ `opencode cli`

จากการทดสอบรันคำสั่งถามเกี่ยวกับโปรเจ็ค **The Middle Way** โดยให้สรุป Milestone v0.4.0 จากไฟล์ `ROADMAP.md` ได้ผลลัพธ์ดังนี้ครับ:

## 1. Gemini CLI (`gemini`)
- **การตั้งค่าเริ่มต้น**: หากไม่ได้ระบุโมเดล ระบบจะพยายามเลือกใช้ `gemini-3-flash-preview` หรือโมเดลอัตโนมัติอื่นๆ ซึ่งในการทดสอบพบว่าติดปัญหา *Rate Limit / No capacity available*
- **เมื่อระบุโมเดลที่เสถียร (เช่น `-m gemini-2.5-pro`)**: สามารถทำงานและตอบคำถามได้**อย่างถูกต้อง รวดเร็ว** และสามารถใช้อ่านไฟล์ในโปรเจ็คเพื่อสรุปข้อมูล Milestone เป้าหมาย 0.4.0 ได้ตรงจุดตามเนื้อหาใน `ROADMAP.md`
- **ข้อดี**: อ่านบริบทจากไฟล์โปรเจ็กต์ได้ดี, ผลลัพธ์จากการตอบภาษาไทยอ่านง่ายและจัดหน้าได้ดี
- **ความเหมาะสม**: เป็นทางเลือกที่ยอดเยี่ยมในการใช้งานแบบ Query หรือเขียนโค้ดตราบใดที่เลือกใช้โมเดลที่ไม่ติด Rate limit

## 2. Opencode CLI (`opencode`)
- **การทำงาน**: ในการทดสอบคำสั่ง `opencode run "..."` รวมถึงพิมพ์ทดสอบด้วยคำสั่งสั้นๆ เช่น `"hello"` หรือรันในโหมด JSON / Print-logs พบว่า **ตัวโปรแกรมค้าง (Hang)** ไม่มีการตอบสนองกลับมาภายในเวลาที่คาดหวัง หรือไม่มีข้อความแจ้งเตือนข้อผิดพลาดที่ชัดเจน
- **ข้อสังเกต**: ถึงแม้ว่าจะมีโมเดลให้เลือกหลากหลายเมื่อรันคำสั่งสืบค้นโมเดล (`opencode models`) เช่น `opencode/gemini-3.1-pro` แต่อาจมีปัญหากับกระบวนการสร้าง session หรือ Environment บางอย่างในระบบ ทำให้ทำงานแบบสั่งผ่าน Command Line ไม่ออก
- **ความเหมาะสม**: การนำไปใช้งานแทน Gemini ตอนนี้อาจจะยังไม่ราบรื่น เพราะต้องตั้งค่าเพิ่มเติมหรือตรวจสอบเรื่อง TUI (Text User Interface) ที่อาจทำให้โปรแกรมค้างเมื่อเรียกใช้งานแบบพื้นฐาน

---

### **🏆 สรุปข้อแนะนำ**

หากต้องการหาเครื่องมือมาแทน Gemini API ที่ราคาแพง แนะนำให้ใช้ **`gemini cli` ร่วมกับการระบุโมเดลที่ชัดเจน เช่น `-m gemini-2.5-pro`** ครับ เนื่องจากตอบโจทย์ในการวิเคราะห์ไฟล์ที่มีอยู่ (เช่น `ROADMAP.md`) ได้ดีมาก และทนทานกว่าการใช้ `opencode` ที่ทดสอบแล้วพบอาการค้างไม่ส่งผลลัพธ์กลับมาครับ
